# Проверка наблюдаемости PredictiveGuard AI

Стенд подняли в отдельном Compose-проекте с новыми томами. В MLflow зарегистрировали CatBoost версии 2 под alias `champion`. Grafana загрузила из репозитория три источника данных, 14 панелей и два правила оповещения.

## Очередь и масштабирование

Источник отправил 330 задач из CSV. Лимит очереди составлял 100 сообщений, задержка inference — 0,5 с, параллелизм — один слот на воркер. Второй воркер подключили во время нагрузки. Скорости измерили в Prometheus на плато, пока очередь оставалась почти полной.

| Показатель | 1 воркер | 2 воркера |
|---|---:|---:|
| Сообщения в очереди (Ready) | 100 | 98 |
| Скорость источника, задач/с | 1,92 | 3,71 |
| Суммарная скорость воркеров, задач/с | 1,96 | 3,80 |

На плато источник публиковал задачи примерно с той же скоростью, с какой воркеры их обрабатывали. После подключения второй реплики пропускная способность выросла почти вдвое.

## Логи, трейсы и алерты

| Сценарий | Результат |
|---|---|
| Успешная HTTP-задача | Один трейс связал HTTP-запрос, публикацию, ожидание в очереди, обработку, inference и запись результата в PostgreSQL. Повторный POST с тем же ключом идемпотентности и запрос статуса вернули исходный `X-Trace-ID`. |
| Поиск задачи в Grafana | Из записи в Loki открыли её трейс в Tempo. Из спана вернулись к логам с тем же trace ID. |
| Переполнение очереди | Алерт очереди перешёл в `Firing`. На дашборде появился HTTP 503. В спанах HTTP и `publish` видны статус `ERROR` и события исключений. |
| Ошибка inference | В одном трейсе видны три неудачные попытки и подтверждённая публикация в DLQ. Алерт DLQ перешёл в `Firing`. |
| Остановка воркера | После SIGTERM задача из состояния `RUNNING` завершилась с первой попытки. После SIGKILL другая задача вернулась в очередь и завершилась со второй попытки. В исходном трейсе появилось событие `rabbitmq.redelivery` с номером доставки 2. |
| Работа без телеметрии | При выключенном Collector задачи от API и CSV-источника обработались. После остановки всех шести сервисов наблюдаемости API и воркер запустили в базовом режиме. Контрольная задача дошла до `SUCCEEDED`. |

Проверили и запрос панели SLO. После успешной обработки задачи доля завершённых задач с результатом за 60 с составила 100%.

## Полная пачка и память

Для проверки полного объёма на том же стенде запустили два воркера с `INFERENCE_DELAY_SECONDS=0.025`, `WORKER_CONCURRENCY=4` и `PREFETCH_COUNT=4`. Источник получил подтверждение публикации **6000 задач за 23,81 с**. Статус каждого из 6000 UUID сверили с PostgreSQL. Все задачи дошли до `SUCCEEDED`.

Наибольший суммарный расход памяти шести сервисов наблюдаемости среди пяти замеров `docker stats` под нагрузкой составил **831,67 MiB** при лимите **1408 MiB**.

## Автоматические проверки

- На Python 3.12 и 3.13 прошли по **56 тестов**. Покрытие сервисного кода составило **93,29%** при пороге 90%.
- Ruff, проверка форматирования, `git diff --check` и разбор всех пяти режимов Compose прошли.
- Миграцию схемы ДЗ 4 проверили на PostgreSQL при одновременном запуске двух экземпляров приложения. Старая задача сохранилась, её трейс, номера доставок и полное время обработки записались корректно.
